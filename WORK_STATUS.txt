PHASE 3 — REAL BACKEND ROUTES (completed August 17, 2026)
- Auth routes expanded: POST /api/auth/refresh (token rotation with DB hash
  validation) and POST /api/auth/logout (refresh token revocation).
- POST /api/auth/verify-otp now persists refresh token hash in RefreshToken
  table, enabling real token lifecycle management.
- Scheme routes: GET /api/schemes (list/search/filter by q, category, state,
  level), GET /api/schemes/:id (detail), GET /api/schemes/:id/related.
- Application routes: POST /api/applications (create), GET /api/applications
  (list mine), GET /api/applications/:id (detail). All auth-guarded.
- Grievance routes: POST /api/grievances (file), GET /api/grievances (list),
  GET /api/grievances/:id (detail). All auth-guarded.
- Notification routes: GET /api/notifications, GET /api/notifications/unread-count,
  PATCH /api/notifications/:id/read, PATCH /api/notifications/read-all.
- Consistent Zod validation and error shape across all routes.
- Unified data service layer (src/services/data.service.ts) keeps
  controllers thin.
- 30 schemes seeded into SQLite DB via src/seed.ts (safe to re-run: upsert).
